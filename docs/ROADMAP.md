# 개발 로드맵: 개인 개발 블로그 (Notion CMS 기반)

전체 범위와 기술 스택은 [docs/PRD.md](PRD.md)를 참고하세요. 총 예상 소요 기간은 약 **9~14일**입니다.

## Phase 1: 프로젝트 골격 (구조, 환경 설정)

**예상 소요 시간**: 1~2일

**작업 내용**
- Next.js 프로젝트 구조 설정
- Notion API 연동 환경 구축
- 기본 레이아웃 구조 생성

**진행 이유**
견고한 기반 없이는 기능 개발이 어려움

**왜 이 순서인가?**
모든 코드는 프로젝트 구조와 개발 환경 위에서 작성되므로, 이후 단계(공통 모듈, 기능 개발)가 올라설 "땅"을 가장 먼저 다져야 합니다. 이 단계가 불안정하면 뒤의 모든 작업을 다시 손봐야 하는 리스크가 있습니다.

**완료 기준**
- [ ] Next.js 15 + TypeScript 프로젝트가 로컬에서 정상 실행됨
- [ ] `@notionhq/client` 설치 및 환경 변수(`.env.local`)로 Notion API 키/데이터베이스 ID 연결 완료
- [ ] 공통 레이아웃(Header/Footer 포함) 뼈대가 모든 페이지에 적용됨

## Phase 2: 공통 모듈 (모든 기능에서 쓰는 것들)

**예상 소요 시간**: 2~3일

**작업 내용**
- Notion API 공통 함수 (`fetchPages`, `fetchPageContent`)
- 공통 컴포넌트 (Header, Footer, Card)
- 공통 타입 정의 (`Post`, `Category`)

**진행 이유**
모든 기능에서 재사용되는 코드를 먼저 만들어야 중복 방지

**왜 이 순서인가?**
Phase 3~4의 글 목록, 상세, 카테고리, 검색 기능은 전부 같은 Notion API 함수·타입·컴포넌트를 가져다 씁니다. 기능을 먼저 만들면 공통 로직이 각 기능 코드에 흩어졌다가 나중에 다시 추출해야 하므로, 뼈대가 잡힌 다음 기능 개발 전에 공통 모듈을 먼저 확정합니다.

**완료 기준**
- [ ] `fetchPages`로 Notion 데이터베이스의 글 목록을 가져와 콘솔에서 확인 가능
- [ ] `fetchPageContent`로 개별 페이지 본문을 가져와 콘솔에서 확인 가능
- [ ] Header/Footer/Card 컴포넌트가 스토리 또는 임시 페이지에서 정상 렌더링됨
- [ ] `Post`, `Category` 타입이 정의되어 Notion 응답 데이터에 타입 적용됨

## Phase 3: 핵심 기능 (가장 중요한 기능)

**예상 소요 시간**: 3~4일

**작업 내용**
- 블로그 글 목록 페이지
- 블로그 글 상세 페이지
- Notion 컨텐츠 렌더링

**진행 이유**
블로그의 가장 기본이 되는 기능

**왜 이 순서인가?**
공통 모듈이 준비된 상태에서 "글을 쓰면 블로그에 보인다"는 이 프로젝트의 핵심 가치를 가장 먼저 완성해야, 전체 흐름이 실제로 동작하는 MVP를 빠르게 검증할 수 있습니다. 카테고리/검색 같은 부가 기능보다 먼저 와야 합니다.

**완료 기준**
- [ ] 홈 화면에서 발행된(Status: 발행됨) 글 목록이 최신순으로 표시됨
- [ ] 글 클릭 시 상세 페이지로 이동하고 본문이 올바르게 렌더링됨 (텍스트, 이미지, 코드 블록 등)
- [ ] 초안(Status: 초안) 상태의 글은 목록/상세에서 노출되지 않음

## Phase 4: 추가 기능 (부가적인 기능)

**예상 소요 시간**: 2~3일

**작업 내용**
- 카테고리 필터링
- 검색 기능
- SEO 최적화

**진행 이유**
핵심 기능이 완성된 후 부가 기능 추가

**왜 이 순서인가?**
카테고리 필터링과 검색은 "필터링/검색할 글 목록"이 있어야 의미가 있고, SEO도 "노출할 페이지"가 있어야 적용할 수 있습니다. 즉 이 단계의 모든 기능이 Phase 3에서 만든 글 목록·상세 페이지를 전제로 하므로, 핵심 기능 완성 이후에만 진행할 수 있습니다.

**완료 기준**
- [ ] 카테고리 페이지에서 선택한 카테고리에 해당하는 글만 표시됨
- [ ] 검색어 입력 시 제목/태그 기준으로 일치하는 글이 필터링됨
- [ ] 각 페이지에 메타 타이틀/디스크립션/OG 태그가 설정됨

## Phase 5: 최적화 및 배포

**예상 소요 시간**: 1~2일

**작업 내용**
- 성능 최적화
- 반응형 디자인 개선
- Vercel 배포

**진행 이유**
기능이 완성된 후 품질 향상

**왜 이 순서인가?**
기능이 바뀌면 최적화한 코드와 레이아웃을 다시 손봐야 하므로, 기능 범위가 모두 고정된 마지막 시점에 최적화와 배포를 진행하는 것이 작업을 반복하지 않는 가장 효율적인 순서입니다.

**완료 기준**
- [ ] 이미지 최적화(`next/image`) 및 불필요한 리렌더링 제거 완료
- [ ] 모바일/태블릿/데스크톱 주요 해상도에서 레이아웃 깨짐 없음
- [ ] Vercel에 배포되어 운영 URL로 정상 접속 및 Notion 글 변경사항이 반영됨
